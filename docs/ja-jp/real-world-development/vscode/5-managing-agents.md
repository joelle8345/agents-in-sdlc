Copilot をエージェントモードにすると、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行を自律的に行います。VS Code の Copilot Chat では、この作業が開発者のコンピューター上でリアルタイムに進むため、ツールの呼び出しとファイル編集を順に確認できます。差分をインラインでレビューし、個別の変更を承認または拒否し、エディターを離れずに追加プロンプトで会話の方向を調整できます。

この演習では、次の内容を学びます。

- アクセシビリティエージェントの作業をリアルタイムで監視する。
- 提案されたファイル編集をレビューして承認する。
- セッションの途中でエージェントに指示し、ハイコントラストに加えてライトモードを追加する。

## シナリオ

[演習 4][previous-lesson] で使ったアクセシビリティ用カスタムエージェントは、ハイコントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加します。新しい会話を最初から始めずに、進行中のセッションに指示して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調査したファイル、実行したコマンド、提案した編集を確認できます。ファイル編集は差分と **Keep** / **Undo** の操作とともにインラインで表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの操作を確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイル編集を提案したら、差分を確認します。
   - **Keep** を選択すると変更を承認します。
   - **Undo** を選択すると変更を元に戻し、エージェントに再試行させます。
4. チャット上部の **Files changed** を開くと、このセッションでエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナルコマンドの実行などに許可が必要な場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドのみ承認してください。

5. エージェントがハイコントラストモードの実装を完了するまで待ちます。最後に、変更の概要が表示されます。

## ライトモードの追加をエージェントに指示する

ハイコントラストモードができたので、同じ会話でライトモードの切り替えを追加します。エージェントは前の作業のコンテキスト、変更したコンポーネント、スタイルの方法、設定したローカルストレージのパターンを保持しています。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントが既存の変更を調べ、ライトモード用の追加変更を提案する様子を確認します。
3. 変更が提示されたら、ハイコントラストの場合と同様にレビューし、各差分で **Keep** または **Undo** を選択します。
4. 望ましくない方向 (たとえば、切り替え UI を好まない形にリファクタリングしようとする場合) に進んだら、チャット入力欄の横にある **Stop** ボタンを選択して停止し、明確な追加指示を送信します。

> [!TIP]
> 進行中のセッションに指示する方が、やり直すより速く済みます。追加プロンプトで調整を依頼できます (「CSS を簡潔にし、セレクターを重複させず CSS 変数を使う」)、方向を修正できます (「3 つ目の切り替えを追加せず、既存の設定パネルにライトモードを統合する」)、範囲を広げることもできます (「両方の切り替えにキーボードショートカットを追加する」)。

## 作業内容をレビューする

コミットする前に、エージェントが変更したファイルを確認します。

1. VS Code の **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストが更新されています。
3. 変更されたファイルをいくつか開いて差分を確認します。ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージによる保存など、カスタムエージェントのアクセシビリティパターンが反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使い、進行中のセッションを監視して方向づけました。ファイル編集を順に確認して変更を承認または拒否し、コンテキストを保ちながら追加プロンプトで作業を拡張しました。

このレッスンでは、次の内容を確認しました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を承認または拒否する。
- 追加プロンプトでセッションの途中に指示する。
